# 실행형 하네스 구현·검증 기록

기준일: 2026-08-13

## 이번 구현 범위

- `gg init`: Codex·Claude Code 어댑터, 정책 사본·해시 잠금, Claude 설정 병합 전 백업, 기존 Git 훅 보존, 선택형 CI 템플릿 생성
- `gg start`·`gg design`: 개인정보·비밀값 형태의 업무 설명 저장 차단, 화면 시안·DB·관리자·외부 연계 결정과 확인 영수증 생성
- `gg build`·`gg verify`: 허용 언어·런타임·패키지 정책·실행기·Hook 변조 차단, L2 이상 설계 확인 및 테스트 생략 차단
- `gg package check`: 정확한 패키지 버전을 `gvskb check-package`로 점검하고 설치하지 않은 채 결과를 증적으로 남김
- `gg verify`: 임의 `npm test`를 자동 실행하지 않음. 사용자의 `--run-tests`가 있을 때만 승인된 `node --test`를 실행. Git 훅에서는 테스트를 실행하지 않음.

실행 명령: `npm test`, `npm run validate:design`, `npm run test:design`.
현재 결과: Node 실행기 회귀 31건, 설계 일관성, 정책 변이 4종 모두 통과.

체커로 이 저장소의 실행 대상 파일 22개를 전체 점검한 결과는 차단 규칙 0건이었다. JSON Schema의 `$schema` URI가 외부 표면 정보 항목으로 표시됐으나, 이는 스키마 식별자이며 하네스 실행 코드의 네트워크 호출은 아니다. 의존성이 없는 `package.json`은 체커가 `unparsed` 정보 항목으로 표시할 수 있어, 하네스는 선언된 의존성이 실제로 있을 때만 이를 불완전 검사로 판정한다.

## 의도적으로 남긴 제한

1. `vibecode-checker`의 CLI JSON에는 안정적인 최종 기계 판정 필드가 없으므로 하네스가 판정을 재계산하지 않는다. 정상 검사도 릴리스는 사람 검토를 요구한다.
2. 승인 번들 manifest, Ed25519 서명·파일 해시 검증, 최소 허용 버전·폐기 목록 기반 업데이트 판정, Inno Setup 설치기 차단형 템플릿, Authenticode 빌드 계약은 구현했다. 실제 기관 코드서명 인증서, 공개키, 내장 Node·체커 실행 번들, 포털 승인 번들 레지스트리, 기관 보호 브랜치 연결은 아직 제공되지 않았다.
3. ChatGPT/Codex 데스크톱과 Claude Desktop은 제품·버전별 MCP 설정 형식이 확정된 뒤에만 별도 어댑터를 구현한다. 현재 실행형 적용 대상은 Codex CLI와 Claude Code다.
4. 프로젝트의 임의 테스트·설치 스크립트를 격리 실행하는 기능은 없다. 따라서 자동 실행하지 않고 명시 실행·CI 격리로 경계를 유지한다.

실제 기관 서명키, 코드서명 인증서, 체커 독립 실행 파일, Node 런타임 번들이 제공되어 새 Windows 계정에서 설치·복구·제거 시나리오를 통과하기 전에는 이 저장소를 “일반 공무원용 원클릭 설치 완료본” 또는 “기관 배포 자동 승인 도구”라고 표현하지 않는다.
