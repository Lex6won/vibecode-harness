# 서버 설치 후 운영 전환 체크리스트

> 작성일: 2026-09-13. 이 문서는 **아직 실행하지 않은** 운영 전환 작업 항목을 기록한다.
> 아래 어떤 항목도 실행하지 않았고, **어떤 항목도 운영승인 상태가 아니다.**
> 상태 값은 다음 다섯 가지만 쓴다: `미실행` / `준비됨` / `시험완료` / `운영승인` / `해당없음`.
> `준비됨`은 저장소에 스크립트나 절차 문서가 이미 있어 곧바로 시험할 수 있다는 뜻이지, 시험했다는 뜻이 아니다. 어느 파일이 근거인지 함께 적는다.

## 상태 기록 규칙

- 상태를 올릴 때는 근거(영수증 경로, 실행 로그, 승인 기록)를 "근거" 칸에 적는다. 근거 없는 `시험완료`·`운영승인`은 기록하지 않는다.
- `운영승인`은 docs/20 의 승인 순서를 거친 결재 기록이 있을 때만 쓴다.
- 하네스 혼자 확인할 수 없는 항목은 포털 저장소의 테스트 이름을 적고 그 결과를 근거로 삼는다.

## 5. 도구별 강제 지점

지원 도구는 다섯 가지다. 각 도구가 정책을 강제하는 지점은 다르며, **모든 도구의 공통 최종 강제 지점은 Git 훅 / PR / CI 다.** 파일 생성 전에 막는 도구는 Claude Code 뿐이고, 다른 도구에 대해서는 그렇게 주장하지 않는다.

| 도구 | 강제 지점 | 파일 생성 전 차단 |
|---|---|---|
| Codex | 프로젝트 지침(`AGENTS.md`) + Git 훅 + `gg verify` | 아니오 |
| Claude Code | 작업 전 훅(PreToolUse) — 파일 생성 전 차단 | 예 |
| Claude Desktop | 프로젝트 안내 + Git 훅/CI | 아니오 |
| ChatGPT/Codex Desktop | 프로젝트 안내 + Git 훅/CI | 아니오 |
| Lovable + GitHub | `VIBECODE-LOVABLE.md` 안내 배치 + GitHub PR/CI 워크플로가 유일한 강제 지점 (`github_pr_gate_required`) | 아니오 |

Google Antigravity 는 2026-09-13 지원 대상에서 폐기됐다. 기존 프로젝트의 잔여 파일은 `gg update` 가 처리한다.

## 6. 인텔 채널 운영 원칙

- `intel-latest` 릴리스는 상태 게이트를 통과한 뒤 **main 에서 매일 자동 갱신**된다.
- `intel-latest-test` 는 수집 코드 변경을 확인하기 위한 것이며, **수동 `workflow_dispatch` 로만** 실행한다. 운영 반입 대상이 아니다.
- 운영 서버로 옮길 때 인텔 캐시·번들은 **그대로 이관**한다. 서버에서 다시 수집하거나 재생성하지 않는다.
