# 적대적 설계 검증과 셀프개선 기록

## 검증 원칙

이 검토는 “AI가 지침을 따른다”는 낙관을 전제로 하지 않는다. 사용자의 실수, AI 도구의 누락, 로컬 훅 우회, 손상된 설치본, 악성 또는 미검증 프로젝트, 네트워크 단절, 개인정보 유입을 가정한다.

## 발견한 문제와 개선

| 실패 가정 | 초기 설계의 문제 | 개선 규칙 | 확인 방법 |
|---|---|---|---|
| 정책 파일을 수정해 Go를 허용 | YAML만 단일 원본이라고 해도 로컬 파일을 바꾸면 우회 가능 | 서명된 bundle manifest, `policy_sha256`, CI 재검증 도입 | lock·manifest 해시 불일치 시 `gg verify` 실패 |
| 취약한 이전 번들로 롤백 | rollback만 있고 하한선이 없음 | 폐기 번들 목록·최소 허용 버전·anti-downgrade 도입 | 폐기·하한 미만 번들 설치와 롤백 모두 차단 |
| `git commit --no-verify` | Git 훅만으로는 우회 가능 | main 보호, CI 재실행, 승인 번들 조건 | 훅을 우회한 PR도 CI가 실패해야 함 |
| Claude Hook이 없는 도구 사용 | Claude 전용 제어를 공통 보안으로 오해할 수 있음 | Codex·Claude 모두 같은 `gg verify`와 Git·CI를 최종 게이트로 사용 | 두 도구에서 같은 정책 실패 코드 확인 |
| 미검증 소스의 test 명령 실행 | `gg verify`가 악성 package script를 실행할 수 있음 | 허용된 템플릿 명령만 기본 실행, lockfile 설치 시 lifecycle script 비활성화, 첫 실행·위험 명령은 사용자 승인, CI는 비밀값 없는 격리 환경 | 미승인 명령·postinstall·외부 쓰기 요청은 중단·기록 |
| Hook과 Git 훅이 서로 재호출 | commit 차단 규칙이 검증 명령 자체를 막을 수 있음 | 검증 영수증과 단발성 환경 표식으로 재진입 방지, CI는 훅을 신뢰하지 않음 | `gg verify` 후 정상 커밋, 실패 시 커밋 차단 |
| 화면 없는 자동화 업무 | 시각 검토 게이트가 불필요한 화면 구현을 강요 | `no_visual_interface` 예외와 사유·입출력 예시·CLI 시나리오 기록을 허용 | UI 없음 예외가 화면 시안 요구를 대체하는지 확인 |
| DB·관리자 질문에 실제 개인정보 입력 | 설계 질문 기록에 민감정보가 들어갈 수 있음 | 실제 이름·민원번호·키·운영 데이터 입력 금지, 예시·범주만 기록, evidence redaction 검사 | 증적 파일의 비밀값·개인정보 패턴 검사 |
| 체커 또는 인텔 확인 실패 | “최신” 또는 “통과”로 과대 표시할 수 있음 | `unknown`, `security_incomplete`, `registry_stale`은 release 차단; 원인과 재시도·오프라인 절차 안내 | 네트워크 차단 fixture에서 release 실패 |
| 화면 시안 확인을 형식적으로만 처리 | 구현 전에 실제 사용자의 확인이 없을 수 있음 | `visual_review_receipt`에 확인한 화면·결정·미결 질문·확인 시각을 기록 | receipt 없으면 DB·관리자·외부 연계 구현 보류 |
| Windows PowerShell이 한글 고정 문구를 다르게 해석 | 설계 검증기가 정상 정책을 누락으로 오탐 | 검증기는 한글 설명 대신 YAML 구조 키와 ASCII 명령·식별자를 검사 | 한글 문서 인코딩과 무관하게 정상·누락 정책을 구분 |

## 남는 한계

1. 로컬 PC의 관리자 권한을 가진 악성 사용자를 하네스가 막을 수는 없다. 기관 배포·CI·서명 번들이 신뢰 경계를 보완한다.
2. AI 도구의 지침 준수 자체는 완전 보장이 아니다. 병합·릴리스 차단은 Git·CI가 담당한다.
3. 체커는 보안성 검토의 증거이며, 공식 보안 승인이나 개인정보 영향평가를 대체하지 않는다.
4. 외부 인텔 조회가 필요한 온라인 점검에서는 패키지명·버전 같은 최소 의존성 메타데이터가 승인 endpoint로 전송될 수 있다. 원본 소스·압축파일·보고서 본문은 전송하지 않는다.

## 재검증 계획

- 정책 일치: Codex·Claude 생성 파일의 정책 버전·언어·검증 명령 비교
- 우회: `--no-verify`, 수정된 lock, 수정된 어댑터, 비공식 번들 fixture
- 실행 안전: 악성 package script, 장시간 테스트, 네트워크 단절 fixture
- 설계: DB·관리자·화면 없음·민감정보·대민 서비스 질문 시나리오
- 릴리스: 서명 실패, 키 교체, 폐기 번들, rollback 하한, 체커 불완전 fixture

개선 사항은 실제 `gg` 실행기 구현 뒤 자동 테스트 fixture로 전환한다. 현재 설계 단계에서는 `validate-design.ps1`이 핵심 정책 파일과 어댑터 기본 일관성을 검사한다.
