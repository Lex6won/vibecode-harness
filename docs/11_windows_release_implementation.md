# Windows 승인 번들 및 설치기 구현 기록

## 구현 범위

이 단계는 일반 사용자 PC에 배포할 Windows 설치기의 신뢰 경계를 코드로 고정한다. 설치기는 승인된 번들만 설치하고, 하네스·Node 런타임·Python 런타임·체커 실행 파일이 모두 포함된 경우에만 빌드할 수 있다.

## 구현한 통제

1. `bundle.manifest.json`은 번들 식별자, 버전, 최소 허용 버전, 파일별 SHA-256, 구성요소 버전, 발급·만료 시각을 담는다.
2. manifest는 기관의 Ed25519 공개키 목록으로 검증한다. 개인키는 저장소, 포털, 설치 PC에 저장하지 않는다.
3. 파일 하나라도 바뀌거나, manifest 서명이 맞지 않거나, 필수 구성요소가 빠지면 `repair_required`로 판정한다.
4. 후보 번들이 현재 설치본의 최소 허용 버전보다 높거나 현재 번들을 폐기 목록에 포함하면 강제 업데이트 대상으로 판정한다. 취약 버전으로의 롤백을 허용하지 않는다.
5. Inno Setup 설치기는 설치 직후 `gg bundle verify`가 성공할 때만 설치를 완료한다. 검증 실패는 설치 중단이다.
6. 설치기 빌드 스크립트는 번들 검증, 체커 독립 실행 파일 존재, Node·Python 런타임 존재, Authenticode 서명 및 서명 검증을 모두 요구한다.
7. `.pem`, `.key`, `.pfx`, `.p12` 및 private·secret 경로는 번들 생성과 검증에서 거부한다. 릴리스 개인키는 HSM 또는 승인된 비밀관리 체계에만 둔다.

## 의도적으로 차단한 것

- 일반 `git pull`로 사용자 PC의 하네스·체커를 교체하는 흐름
- 서명되지 않은 ZIP 또는 개발 폴더를 공식 설치본으로 표시하는 흐름
- 코드서명 인증서, 타임스탬프 서버, 승인 공개키 없이 설치기를 만드는 흐름
- 체커가 Python 패키지인 상태를 감춘 채 Python 미설치 PC용 설치기를 만드는 흐름

## 배포 전 선행 조건

1. 체커 저장소 담당자가 승인된 Windows 독립 실행 파일 또는 포함형 Python 런타임 번들을 공식 릴리스로 제공해야 한다. 이 하네스 저장소는 체커를 수정하지 않는다.
2. 기관은 Authenticode 코드서명 인증서와 Ed25519 릴리스 서명키를 HSM 또는 승인된 비밀관리 체계로 운영해야 한다.
3. `shared/trust/approved-signers.json`에는 공개키만 등록한다. 운영 설치기에는 해당 신뢰 루트를 포함하고 설치 파일 자체는 Authenticode로 서명한다.
4. 포털은 승인된 설치 파일, manifest 해시, 릴리스 노트만 HTTPS로 제공한다. 브라우저가 설치를 자동 실행하거나 localhost API를 직접 호출하지 않는다.
5. Node·Python·Git가 전혀 없는 새 Windows 사용자 계정에서 설치, `gg doctor`, Codex·Claude Code 어댑터 적용, 제거, 복구를 검증한다.

## 현재 한계

이 저장소에는 실제 기관 서명키, 코드서명 인증서, 체커 독립 실행 파일, Node 배포 런타임이 없다. 따라서 현 상태는 **서명된 설치 파일을 만들기 위한 차단형 구현과 테스트**이며, 실제 배포 EXE가 아니다.
